# CLAUDE.md — working in qa-e2e-pilot

This repo is a **Claude Code plugin**, not an app. It ships an agent, three commands (`/qa-run`, `/qa-roles`, `/qa-resume`), and nineteen skills that perform full-stack browser QA. Claude needs no build step (the root `agents/`/`commands/` files ARE what Claude loads); the other three harnesses are generated by `scripts/build-adapter.sh` into git-ignored `dist/`. There **is** a runtime test suite: `tests/<suite>/run.sh` (80 suites — 65 engine, 15 qa-kit), gated by `scripts/run-engine-ci.sh` / `qa-kit/scripts/run-qakit-ci.sh` and enforced complete by `scripts/check-suite-coverage.sh`; "tests" also covers the static validation + functional smoke-tests described below.

**Two plugins live here.** `qa-e2e-pilot` (repo root) is the **verification engine**. `qa-kit/` is an optional, step-gated **process shell** built on it — a *second* plugin with its own manifest, commands, scripts, and agent that declares `dependencies: ["qa-e2e-pilot"]` and reuses the engine's skills by qualified slug (`/qa-e2e-pilot:<skill>`). **The engine must stay byte-for-byte unchanged when working on qa-kit** (`core/`, root `commands/`/`skills/`/`scripts/`, `qa-verify.sh`, the byte-oracle) — qa-kit is purely additive. qa-kit runs on **all four harnesses** since increment 7 ([ADR-0024](./docs/adr/0024-qa-kit-multi-harness.md)): Claude ships as the dependencies-model plugin; Codex/Pi/opencode are generated from `qa-kit/core/` (qa-kit-owned copy of the ADR-0017 pipeline) into git-ignored `qa-kit/dist/<h>/`, engine still untouched. See [ADR-0022](./docs/adr/0022-qa-kit-process-shell.md), [ADR-0024](./docs/adr/0024-qa-kit-multi-harness.md), [`qa-kit/README.md`](./qa-kit/README.md), and the `qa-kit-plugin-packaging-facts` memory (per-plugin `${CLAUDE_PLUGIN_ROOT}`; no symlinks; `commands` is a dir not an array).

## Read these first

- **[CONTEXT.md](./CONTEXT.md)** — the ubiquitous language. Use these words exactly: *criterion/step/run*, *baking*, *multiplicity*, *oracle*, *reconciliation*, *verdict*, *confidence*, *suspected layer*, *driver/session*, *probing*, *memory-spec*, *checkpoint*. Don't invent synonyms.
- **[docs/adr/](./docs/adr/)** — the hard-to-reverse decisions: 0001 reimplement opslane patterns (don't fork/vendor), 0002 run state in `.qa/runs/` not agent memory, 0003 sequential verification (narrow parallel pool), 0004 per-project `.qa/config.json`, 0017 multi-harness portability (shared core + generated adapters, Claude byte-oracle), 0022 qa-kit process shell (2nd plugin, dependencies model, `qa-verify` untouched), 0023 qa-kit TDQA data layer (origin baseline + pinned fixtures + check-fixtures; engine untouched), 0027 fail fast at record time + read the real driver shapes + one sanctioned recorded write for `api-write` criteria, 0028 mandatory bound screenshots + the rendered (never hand-written) report, 0029 one authoritative verdict per criterion (supersession) + record-time identity guard + implicit phase windows, 0030 surface census + `ship|smoke|full` run profiles + read-only crawl safety, 0031 journeys in the engine's checklist schema (`journeys.json` + row `journey`/`variant`/`priority`/`surfaceId`), 0032 trusted-verdict gates (oracle / state / data policy at record time, mirrored in `qa-verify`, plus the computed ship verdict and the bug export), 0033 independent re-adjudication (a fresh-context verifier that may only downgrade).

## Invariants (do not break)

- **Verdicts are exactly** `pass | fail | blocked | deferred | error`. **Confidence** is orthogonal: `high | low` (low when the expected value could only come from backend code). Never add a sixth verdict (`skip`/`warn`/`partial`).
- **Suspected layer** is exactly one of `FE | route | service | migration | DB`. Recorded on a `fail`; flows into the report and bug-log.
- **The oracle is the spec/domain rule, never the backend's own formula.** `verifying-computed-logic` recomputes independently; reading backend code only *localizes* a divergence.
- **Run state lives in `.qa/runs/<run-id>/`** as plain files — never the agent's personal memory / `MEMORY.md` (ADR-0002).
- **Verification is sequential by default** (ADR-0003). Parallel fan-out is opt-in, only for tagged independent/read-only criteria + deliberate race tests, capped at `maxParallel`.
- **Probing is read-only** unless `allowApiWrites` *and* the disposable-env marker are set. **Secrets never printed.**
- **Browser tools are called by capability**, naming the Playwright MCP tool in parens (e.g. `browser_snapshot`). New drivers drop in via config, not code.
- **The action-under-test is performed through real UI affordances only** (ADR-0015). `human-action` is an evidence **kind**, never a verdict. The act phase uses human-path tools (click/type/…); a mutating `browser_evaluate`/`route`/direct write on the act path is a workaround the gate rejects. A UI-impossible action is `fail@FE` (confidence high); a genuine tool limitation is a logged `--nonui-reason` opt-out (confidence low). Never weaken the gate to force a `pass` through.
- **qa-kit never modifies the engine** (ADR-0022). The `qa-kit/` process shell is additive: it reuses the engine's skills by qualified slug and bundles its own scripts under `qa-kit/scripts/` (per-plugin `${CLAUDE_PLUGIN_ROOT}` — it cannot reference the engine's files). `qa-verify` stays untouched; qa-kit's out-of-plan-act enforcement is a *separate* `qa-kit/scripts/verify-plan.sh` run beside it. The constitution regenerates roles **wholesale** (ADR-0011) + an informational diff; per-role customization is a per-spec concern, never the constitution.
- **The census crawl is read-only on every environment** (ADR-0030). `taking-surface-census` follows only links, tabs and menu/dialog openers that `crawl-safety.js` classifies safe (English + Arabic destructive labels; unsafe always wins; anything not allowlisted is unsafe), never types or submits, answers native dialogs `accept:false`, stops clicking for a persona after any observed non-GET request, and is skipped on production unless `allowBlackboxCrawl`. Anything it will not touch is `unexplored` with a reason. Never loosen the classifier to grow the census.
- **Profiles fill defaults, never override** (ADR-0030). `scripts/profile.sh resolve` turns `ship|smoke|full` into `.qa/runs/<run-id>/effective-config.json`, which every phase after pre-flight reads; a key the user set wins, including an explicit `[]`. `full` (the default) adds nothing. Stack specifics live only in `adapters/census/<stack>.sh`, run through `exec.prefix`; nothing is hard-coded to one stack or project. Ship rows add kinds `load-clean | deny | input-validation` (no new verdict, no new evidence kind); `input-validation` always requires `bake`.
- **Gates only refuse or downgrade** (ADR-0032/0033). No gate, mirror, re-adjudication or renderer step may turn a non-pass into a pass or raise a confidence. `checkpoint.sh` runs three trusted-verdict gates on every `pass`, each refusing with exit 1 and a one-line `<NAME> GATE:` message: **ORACLE GATE** (a row with `fixture.expect.oracleSource`, or under `ship` any `computed-logic|business-rule` row, passes at `confidence: high` only with `oracleSource` `human` or `spec` — `spec` needs a contained `citation` `<path>:<line>` that `check-fixtures.sh` resolves; low confidence is always allowed), **STATE GATE** (a pass on a mutating row per `mutation-flag.sh` needs `bake` or `probe` in `--kinds`; `--nonui-reason` does not bypass it; **applies in every profile — a behaviour change vs 0.11.0**: a rejected write passes on a bake at multiplicity 0, never `human-action` alone, and never by marking the row `mutates:false`), and **DATA POLICY GATE** (only with `gates.dataPolicy: enforce`: the typed values in the row's `action-trace.json` — step `text`/`value`/`values`/`fields[].value`, password-like fields skipped, passed as a mode-600 `@file` — must pass `data-policy.sh check`; `input-validation` rows skip date window and email domain). `qa-verify.sh` mirrors all three (checks 3.6–3.8, reasons `oracle-ungrounded|no-state-evidence|data-policy-violation`, failing closed on any confidence other than `low`, `invalid-confidence` for anything outside `high|low`) and adds the `effectiveConfigMissing` run check: a config or spec run-config naming `ship` or `dataPolicy: enforce` with no `effective-config.json` in the run fails the run. Keep the two copies in parity (`tests/verify-ship-gates`).
- **Re-adjudication is independent and downgrade-only** (ADR-0033). `re-adjudicating-verdicts` re-judges every low-confidence pass and every UX-promoted fail with one fresh subagent per evidence bundle; the bundle is an allow-list of persisted evidence and never carries the journal, the toolstream or the agent's prose. A disputed pass becomes `blocked` (`verifier-disagrees: <reason>`), a disputed fail drops to `confidence: low`; `adjudication.sh apply` refuses any upgrade. Capability is `harness-profiles.json` `subagentDispatch` (claude only today); elsewhere it prints the unavailable banner and exits 0 — never re-judge in the acting context. On Claude the dispatched agent cannot start agents, so `/qa-run` (and `/qa-resume`) runs it after the agent returns and re-renders. **End-of-run order: `qa-verify` → re-adjudication (select uses verification-adjusted confidence) → `qa-verify` again → bug export → render report.** A P1 record the verifier disputed, or a P1 low-confidence pass nobody re-judged, blocks SHIP-READY, and the report carries a **Re-adjudication** line. `gates.oracle` is informational: enforcement keys on `oracleSource` and `ship`. qa-kit's `/qa-verify` also runs `verify-plan.sh --drift` (trust-field drift between the run and frozen checklists fails).
- **qa-kit TDQA data layer** (ADR-0023). A spec declares a provenance-aware `data-baseline.json` (`origin: seeded|created`, tenant-`scope`d — NOT "provenance", which is `provenance.sh`'s word); `/qa-scenarios` pins per-criterion `actionInput`+expected into the prose oracle (engine reads it natively) + a structured `fixture` field. Computing criteria (`kind ∈ {computed-logic, business-rule}`) must carry a well-formed pinned expect — `check-fixtures.sh` gates that presence/shape (including a valid `oracleSource`). Since 0.12.0 the `confidence: high` requires `oracleSource` `human`/`spec` mapping is enforced at record time by `checkpoint.sh`'s ORACLE GATE (ADR-0032) wherever a row carries `oracleSource` or the profile is `ship`; `check-fixtures.sh` still only checks presence/shape and `spec` citations. The seeded baseline fixes the multiplicity-0 oracle (empty = measured baseline, not 0). Establishment is declare-and-verify by default (6a writes nothing); **6b adds an opt-in, disposable-env-only auto-seed**: `detect-seed.sh` proposes the stack's seed command by READING `stack-profile.json` (it does NOT modify the `detecting-stack-profile` engine skill), `auto-seed.sh decide` gates the write (`allowApiWrites` + non-empty `seedableEnvMarker` + `environment != production`, mirroring the engine's write gate), and `/qa-spec` runs it only after human confirmation. Still engine-untouched.

## Skill conventions (when adding/editing a skill)

- Frontmatter has **only** `name` + `description`. `name` **must equal the directory name**, be lowercase-hyphen, gerund, ≤64 chars, and not contain "claude".
- `description` is third-person, ≤1024 chars, starts with "Use when …", and states WHAT + WHEN.
- Body **< 500 lines**, imperative, checklist-structured (plan → validate → execute). References one level deep.
- Bundle **scripts** (executed) and **templates** (copied) — don't inline large artifacts into the body.
- Include **≥3 mini-evals** drawn from the 14 real session bugs (see the plan / the existing skills for the bug list).

There are **19 skills**: the 9 core verification skills (`analyzing-feature-ui`, `checkpointing-qa-memory`, `driving-browser-qa`, `generating-qa-checklist`, `probing-apis-through-browser`, `verifying-backend-persistence`, `verifying-computed-logic`, `walking-multistep-flows`, `writing-qa-reports`) + `fanning-out-criteria` + spec-kit `ingesting-spec-kit` + role discovery (`discovering-user-roles`, `confirming-discovered-roles`) + `detecting-stack-profile` + `detecting-visual-ux` + `detecting-interaction-ux` + `bootstrapping-qa-config` + `taking-surface-census` (the read-only per-role crawl behind `.qa/census.json`) + `re-adjudicating-verdicts` (the fresh-context second judge, ADR-0033). Top-level `scripts/` (not skills, see the Layout block above for the full list): `report-to-junit.sh` (CI export), `qa-ci.sh` (turnkey CI: preflight→agent→junit, pluggable via `QA_AGENT_CMD`/`QA_PREFLIGHT_CMD`), `qa-verify.sh` (out-of-agent deterministic re-check), `memory-sync.sh` (gated Mem0/vector write-through of durable artifacts only), `block-hook.sh`/`capture-hook.sh`/`check-prereqs.sh` (plugin hooks wired via `.claude-plugin/plugin.json`), `run-engine-ci.sh`/`check-suite-coverage.sh` (the local + CI suite gate), `classify-finding.sh` (deterministic disposition of ONE observed browser error — prints `originClass=<in-scope|third-party|benign>` + `statusClass=<fatal|non-fatal>`; the two strings are a contract the findings ledger and `qa-verify.sh` consume), `render-report.sh` (renders `report.html`/`report.md` for any run from its record — thumbnails, full-screen viewer, `--embed`; ADR-0028), `known-defects.sh` (`validate` the project-level `.qa/known-defects.json` registry — schema, 90-day expiry cap, `observedClass`-gated severity floor — and `status` each entry `outstanding|expired|cleared`), and the ship-QA scripts (ADR-0030/0031): `census.sh build` (merges a stack adapter's surfaces — written to `.qa/census/adapter.json`, adapter picked by the stack-profile `framework` id, else `generic` — with the per-persona crawl files into `.qa/census.json`; each surface carries `sampleUrls` per persona, and crawl tab/dialog/sheet visits become `<parent>#<kind>:<subKey>` surfaces; diffs `unreachable`/`overreach`/`crawlOnly`; a failed adapter degrades to crawl-only with an `adapter-failed:` warning and `adapterOk:false`, never an empty "all covered"), `profile.sh resolve` (effective config + `profileSources`), `journeys.sh validate|status|expand-variant` (`expand-variant` prints only the new variant rows; the caller appends them), `data-policy.sh check|record|list` (forbidden markers, email domain, date window — `--kind input-validation` skips the last two; generated record data only, passed as `@file`, credential-like fields masked; created-record ids for cleanup; `checkpoint.sh`'s DATA POLICY GATE calls it under `enforce`), and the trusted-verdict scripts (ADR-0032): `render-report.js` opens the report with **Ship readiness** (`SHIP-READY` / `NOT SHIP-READY` with every failing condition; fails closed on missing coverage, journeys or verification) whenever the run has `coverage.json`/`journeys.json` or the profile is `ship`, and `bug-export.sh <run-dir> --out <dir> [--known-defects <registry>]` (tracker-neutral `bugs.json` + one plain-language `<id>.md` per new bug from `bug-log.json` and from verifier overrides that show a contradiction; evidence-gap overrides go to `needs-recheck.json`, counted on the ship summary's informational **Needs re-check** row; a re-export prunes only the stale `.md` files it listed itself; bugs without evidence fall back to recorded evidence refs or `evidence/<crit>/`; outstanding known defects become `duplicateOf`; secrets redacted). qa-kit adds `qa-kit/scripts/migrate-inverted-criterion.sh` (lifts a criterion that asserts an application failure out of a frozen `checklist.json` into that registry, then **exits 2 — its success path** — because `ticket`/`expiry` cannot be auto-filled), `surface-access.sh derive|confirm-table|apply` (who SHOULD reach each surface; on a hinted surface crawl reach without a matching hint is never `allowed` until a human confirms it; on a hint-less surface `allowed` = crawl `reachedBy` with source `crawl`, listed as `reachedWithoutEvidence` too, which is no permission evidence and yields no deny rows — it only keeps the overreach diff quiet), `generate-ship-criteria.sh` (census → load-clean / deny / ownership-isolation / input-validation / ux-revisit rows; deny rows only where permission evidence exists) `coverage.sh` (role × surface coverage; `--mode block` exits 1 on any uncovered pair, an empty census, or a failed adapter without `--accept-crawl-only`) and `oracle-confirm.sh render|apply` (the offline oracle confirmation page `/qa-analyze` step 4c renders for unconfirmed computed rows, grouped by business rule; `apply` writes accepted/edited values back as `oracleSource: "human"`). Drivers map to tools via `skills/driving-browser-qa/references/driver-capabilities.md`. Docs `running-in-ci.md` and `extending-drivers.md` cover later-phase capabilities. `install.sh` globs `skills/*/`, so new skills are picked up automatically.

**Human-interaction discipline (ADR-0015).** State-mutating criteria are tagged `human-action`; their `pass` is gated by `checkpoint.sh` via an act-phase workaround lint + mandatory before/after state fingerprints (`check-action-trace.js`), and — when the Playwright MCP is run with `--save-session` (opt-in; not the default managed instance) — an additional reconciliation of the recorded act against that independent log (`parse-session-log.js`), which closes the self-report hole. Without `--save-session` the gate runs the lint+fingerprint checks and flags that independent verification was unavailable. The act phase is UI-only; a UI-impossible action is `fail@FE` (confidence high), not a workaround; a genuine tool limitation is a logged low-confidence `--nonui-reason` opt-out. See `skills/driving-browser-qa/references/interaction-discipline.md`.

## Bundled scripts depend on jq OR python3

`checkpoint.sh` prefers `jq`, falls back to `python3`, and errors clearly if neither is present; `report-to-junit.sh`, `memory-sync.sh`, and `find-spec-kit.sh` use `python3`/`jq` similarly (`memory-sync.sh` also needs `curl` for a real send). `preflight.sh` has a DIFFERENT fallback chain — `jq` → `node` → `grep` (never `python3`; degrades gracefully, skipping driver enumeration rather than failing, if neither `jq` nor `node` is found). Browser-context JS (`react-set-input.js`, `click-by-text.js`, `backend-probe.js`) is injected via the evaluate tool — write it as dependency-free browser code (`document`/`window`/`fetch`).

## Releasing (both plugins)

Marketplace installs track `main`, but the **official release artifact is the git tag**
`{plugin-name}--v{version}` — Claude Code resolves plugin dependency **version constraints only
against these tags** (an unversioned dependency works untagged; a `~x.y.z` constraint fails without
one). Per release: (1) bump the version in ALL its sites — engine: `.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json` (metadata + entry), `scripts/skills.json`; qa-kit:
`qa-kit/.claude-plugin/plugin.json` + its marketplace entry; (2) merge to `main`; (3) tag the merge
commit `qa-e2e-pilot--v<X>` / `qa-kit--v<Y>` (`claude plugin tag --push`, or plain
`git tag` + `git push origin <tag>`) — the tagged tree's plugin.json MUST carry the same version.
Tags exist for every release since 0.6.3/0.1.1. GitHub Releases are not consumed by the plugin
system (optional, human-facing only).
