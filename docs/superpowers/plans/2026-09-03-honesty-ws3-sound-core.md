# Honesty WS-3 Sound Core (Plan H2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move QA-evidence enforcement into a trust domain the run's agent does not control — a **capture-hook** (`PostToolUse` → append-only `.qa/runs/<run>/toolstream.jsonl`, secret-redacted), a **block-hook** (`PreToolUse` denying the phase-independent absolutes: a mutating `browser_evaluate`, `browser_run_code_unsafe`), **provenance binding** (a `pass`'s evidence must correspond to a captured call), and a local, deterministic **`qa-verify`** that re-checks a run's evidence + provenance against the toolstream and overrides a forged in-run `pass`.

**Scope note — this is Plan H2 of the honesty-hardening effort (spec `docs/specs/2026-09-02-qa-honesty-hardening-design.md`, ADR-0018).** It ships the spec §12 "sound core": capture-hook + block-hook + local `qa-verify` + provenance binding, **Claude-first** (§4/§12). **Plan H3** is the fast-follows: persona-identity (#6), clock (#7), WS-2 doctrine, and the Codex/opencode/Pi hook adapters. H1 (already merged) built `required-kinds.sh` + `checklist.json`; qa-verify reuses `required-kinds.sh` verbatim for its independent required-kinds re-derivation.

**The one limit, stated plainly (spec §1):** a referee the player runs cannot be made fully sound in-agent — an agent with `Bash` can edit the hook scripts or the toolstream on an unhardened install. So the **live hooks are tamper-*evident*, best-effort**; the **authority is `qa-verify`**, run out-of-agent (operator or CI). On an unhardened install the report prints the actual assurance tier + "authoritative verdict is `qa-verify`." No hash-chain (an agent can recompute it → false assurance; cut per spec decision #2). Real tamper-*resistance* needs the hardened tier (managed/sandbox), documented, not built here.

**Architecture:** New `scripts/` enforcement scripts (NOT `core/enforcement/` — the generator copies `scripts/` verbatim into `dist/` and the CI static-sweep covers it; `core/` is neither, so the spec's `core/enforcement/*` naming is superseded by `scripts/`). `capture-hook.sh` (PostToolUse) resolves the active run via Plan B's `.qa/runs/latest`, redacts `Bash` args against a config secret-pattern list, and appends `{seq,ts,tool,args,resultDigest,responseBody?}` lines to `toolstream.jsonl`. `block-hook.sh` (PreToolUse) reuses `parse-session-log.js`'s `mutates()` classifier on a `browser_evaluate` payload and denies (exit 2 + deny JSON) a mutating one + `browser_run_code_unsafe`. Both are wired into `.claude-plugin/plugin.json`'s inline `hooks` object (sibling to the existing `SessionStart`). `qa-verify.sh <run>` deterministically re-checks each `pass`: re-derives required-kinds (`required-kinds.sh`), re-validates evidence structure/values, binds provenance (the bake/probe read-back's value or key must appear in some captured toolstream response — a containment check), and runs the classifier on act steps; it writes `verification.json` per criterion and exits non-zero if any `pass` fails. The **independent re-drive/re-bake** of high-stakes criteria (spec §5.3) is invoked by the operator/CI via a pluggable `QA_VERIFY_REDRIVE_CMD` (like `qa-ci.sh`'s `QA_AGENT_CMD`) — structured here, but its LLM re-drive is not unit-tested (needs a fresh agent session), documented as the hybrid's second half.

**Tech Stack:** Bash (`set -uo pipefail`), `jq` preferred / `python3` fallback, dependency-free Node (reusing `parse-session-log.js`'s `mutates()`), Claude Code plugin hooks (`PostToolUse`/`PreToolUse`, JSON-on-stdin, exit-2 deny — confirmed against current docs). Reuses H1's `required-kinds.sh` + `mutation-flag.sh`; Plan B's `.qa/runs/latest`.

## Global Constraints

- **`jq` preferred / `python3` fallback / `die`; no NEW hard `node` dep** (the block-hook reuses the existing dependency-free `parse-session-log.js` via `node`, matching `check-action-trace.js`'s precedent — the hook is a JS-capable path; `capture-hook.sh`/`qa-verify.sh` stay jq/python3). Honor the has_jq/has_py idiom.
- **Hooks live in `.claude-plugin/plugin.json`'s inline `hooks` object** (sibling to `SessionStart`), pointing at `${CLAUDE_PLUGIN_ROOT}/scripts/<hook>.sh`. Confirmed contract: hook script reads JSON on stdin (`tool_name`, `tool_input`, `tool_response`); PreToolUse denies via **exit 2** (+ optional `{hookSpecificOutput:{hookEventName:"PreToolUse",permissionDecision:"deny",permissionDecisionReason:"…"}}` on stdout); PostToolUse records (exit 0). `.claude-plugin/plugin.json` is hand-maintained (NOT generated by `build-adapter.sh`) — edit it directly.
- **The capture-hook is the sole toolstream writer** (append-only `>>`), resolves the run via `.qa/runs/latest`, and is a **no-op when there is no active run** (no latest pointer / run dir). It must be **fast + never fail the tool call** (a hook that errors must still `exit 0` for PostToolUse — never block a legit call by crashing).
- **Secret redaction (spec §5.1):** `Bash` args are redacted against a config secret-pattern list (`enforcement.secretPatterns`) + config-declared credentials (`auth`, any `*Env` var *values*) before writing. `browser_*` args are written in full (test data) — **documented residual:** a `browser_type` into a password field can capture a typed secret; note it, don't silently claim full secret safety. Secrets never printed to the toolstream or stdout.
- **Block-hook = phase-independent absolutes ONLY (spec §5.2).** Deny a mutating `browser_evaluate` (via `mutates()`) and `browser_run_code_unsafe`. Do **NOT** live-block `browser_navigate` (legit arrange-entry — record-only → `qa-verify`). Live-block false-positives near-zero. All nuanced checks (provenance, fingerprint-target, persona-identity, required-kinds) are record-only → `qa-verify`, never the live hook.
- **`qa-verify` is deterministic + authoritative (spec §5.3).** No LLM in its core. It re-derives required-kinds (`required-kinds.sh` — never trusting the agent's), re-validates evidence, binds provenance (containment against the toolstream), runs the classifier; writes `verification.json`; a run is "verified" only when every `pass` survives; on disagreement the verifier's verdict wins (pass→fail/blocked) and un-reverified human-action/cross-tenant passes are `confidence: low` + banner. The re-drive half is a pluggable operator/CI step (`QA_VERIFY_REDRIVE_CMD`), documented, not unit-tested here.
- **No hash-chain** (false assurance — cut, spec decision #2). Trust comes from `qa-verify` corroborating the toolstream, not the file.
- **Reuse, don't rebuild:** `required-kinds.sh derive`, `mutation-flag.sh`, `parse-session-log.js`'s `mutates()`/`classify()`, Plan B's `.qa/runs/latest`, H1's `checklist.json`. The toolstream (JSONL) is qa-verify's provenance source; the `--save-session` `session.md` remains `check-action-trace.js`'s act-trace source — two complementary independent records (document the seam; do NOT repoint `mutation-flag.sh reconcile`, which stays session.md + absent-tolerant).
- **Portability + CI:** enforcement scripts under `scripts/` are copied into `dist/` + covered by `validate-adapters.sh`'s static sweep. After edits: dist regen, `validate-adapters.sh` exit 0, `tests/portability/run.sh` `FAIL=0` (no `grep -P`/`perl`). `dist/` git-ignored. The `.claude-plugin/plugin.json` change must keep it valid JSON (the sweep parses it).
- **Commit messages: NO Claude/Anthropic attribution, NO `Co-Authored-By`.**

### Task 1: Toolstream writer + capture-hook (`PostToolUse`) + secret redaction

**Files:**
- Create: `scripts/toolstream.sh` — the append helper + a JSONL reader (`toolstream.sh append <run> <event-json>`; `toolstream.sh read <run>` → the events; `toolstream.sh redact <bash-args-json> <config>` → redacted).
- Create: `scripts/capture-hook.sh` — the `PostToolUse` hook: read stdin JSON, resolve run via `.qa/runs/latest`, build `{seq,ts,tool,args,resultDigest,responseBody?}`, redact Bash args, append via `toolstream.sh`. No-op if no active run. Always `exit 0`.

- Create: `tests/toolstream/run.sh`, `tests/capture-hook/run.sh`

**Interfaces:**
- `toolstream.sh append <run> <event-json>` → appends one canonical line to `.qa/runs/<run>/toolstream.jsonl` (append-only; a `seq` monotonic per file; `ts` stamped here). `read <run>` → all events (jq-selectable). `redact <args-json> <config-json>` → args with any substring matching a `secretPatterns` regex or a declared credential value replaced by `"<redacted>"`.

### Task 2: Block-hook (`PreToolUse`) — phase-independent absolutes

The live deny layer: a mutating `browser_evaluate` and `browser_run_code_unsafe` are denied before running. Reuses `mutates()`.

**Files:**
- Create: `scripts/block-hook.sh` — the `PreToolUse` hook: read stdin JSON; if `tool_name` is `browser_run_code_unsafe` → deny; if `browser_evaluate` and `mutates(tool_input.function/code)` → deny (exit 2 + deny JSON); else exit 0. `browser_navigate` → NEVER blocked (exit 0; record-only is the capture-hook's job).
- Modify: `.claude-plugin/plugin.json` — add a `PreToolUse` entry (matcher `mcp__plugin_playwright_playwright__browser_(evaluate|run_code_unsafe)`) → `block-hook.sh`.
- Create: `tests/block-hook/run.sh`

**Interfaces:**
- `block-hook.sh` (stdin = hook JSON): a mutating evaluate (e.g. `fetch(...,{method:'POST'})`, `.setItem(`, `page.request.post(`) → **exit 2** + `{hookSpecificOutput:{hookEventName:"PreToolUse",permissionDecision:"deny",permissionDecisionReason:"mutating browser_evaluate is never sanctioned (arrange via gated API/type, observe read-only)"}}`; a read-only evaluate (`document.querySelector`, a GET fetch) → exit 0; `browser_run_code_unsafe` → exit 2; `browser_navigate` → exit 0. Reuse `parse-session-log.js`'s `mutates()` (the same semantic classifier H1's WS-1 #3 hardened) via `node`.

### Task 3: Provenance binding on evidence

Make each evidence artifact bindable to a captured call, and record the binding. A `pass` whose evidence corresponds to no captured toolstream call is the AC-1 forgery case `qa-verify` (Task 4) rejects.

**Files:**
- Modify: `skills/checkpointing-qa-memory/scripts/record-evidence.sh` — `bake`/`probe`/`action-trace` writers gain an optional `--source-ref <toolstream-selector>` recorded as `provenance: {sourceRef, boundAt}` (the agent's claim of which captured call produced it); when absent, `qa-verify` falls back to containment. Keep back-compat (absent → today's shape).
- Create: `scripts/provenance.sh` — `provenance.sh check <run> <artifact-json>` → given an evidence artifact, verify its read-back value/entity-key appears in SOME captured toolstream response (containment) OR its `sourceRef` resolves to a real toolstream entry. Prints `bound|unbound|no-toolstream`.
- Create: `tests/provenance/run.sh`

**Interfaces:**
- `provenance.sh check <run> <artifact-json>` → reads `.qa/runs/<run>/toolstream.jsonl`; for a bake, the `readBack` value or the entity key must be contained in some captured `responseBody`; for an action-trace, its `sessionCalls`/act must correspond to captured `browser_*` calls; returns `bound` (found), `unbound` (a `pass`'s evidence with no matching capture → forgery signal), or `no-toolstream` (absent → best-effort degrade, not a hard fail here — qa-verify decides confidence).
- Containment is a **substring/key-presence** check (formatted-in-DOM ≠ stored value, so no exact equality), per spec §5.4.

- [ ] **Step 1** — tests: a bake artifact whose `readBack` value appears in a captured toolstream response → `bound`; a bake whose value appears in NO captured response → `unbound` (the forgery signal); no toolstream → `no-toolstream`; an action-trace with `sessionCalls` matching captured browser calls → `bound`, with none → `unbound`. Run → FAIL.
- [ ] **Step 2** — implement `provenance.sh` (containment via jq/python; bounded-body scan) + add `--source-ref`/`provenance` to record-evidence.sh (back-compat: absent → today's shape; existing action-trace/checkpoint tests stay green).

### Task 4: `qa-verify` — deterministic re-check + reconciliation

The out-of-agent authority. Re-checks each `pass` deterministically and writes `verification.json`; a forged pass with no matching capture is overridden.

**Files:**
- Create: `scripts/qa-verify.sh` — `qa-verify.sh <run>`: for each `criterion_verdict pass` in the run, (1) re-derive required-kinds via `required-kinds.sh` (from `checklist.json`) and check recorded kinds ⊇ derived; (2) re-validate each evidence artifact's structure/values (reuse the gate's checks / `check-action-trace.js` for human-action); (3) bind provenance via `provenance.sh check` (an `unbound` pass → override to `fail`/`blocked`); (4) run the classifier on act steps + flag any `browser_navigate` used off-Verify-phase (record-only from the toolstream). Write `.qa/runs/<run>/verification.json` = `[{criterionId, inRunVerdict, verifierVerdict, confidence, reasons[]}]`. Exit non-zero if any `pass` fails verification.
- Create: `tests/qa-verify/run.sh`
- Create: `tests/qa-verify/fixtures/` — a verified run + a forged run (`action-trace.json` with `sessionCalls:[]`, equal fingerprints, no matching capture).

**Interfaces:**
- `qa-verify.sh <run>` → `verification.json` + exit code (0 = all passes verified; non-zero = ≥1 override). Reuses `required-kinds.sh`, `provenance.sh`, `check-action-trace.js`. Deterministic (no LLM). The pluggable re-drive step: if `QA_VERIFY_REDRIVE_CMD` is set, invoke it per high-stakes criterion (documented; not unit-tested).
- Reconciliation: the verifier's verdict wins; an un-reverified human-action/cross-tenant pass → `confidence: low` + a `reason`. The run banner ("verified"/"unverified") is derivable from the exit code.

- [ ] **Step 1** — tests: **AC-1** — a forged `action-trace.json` (`sessionCalls:[]`, equal fingerprints, fabricated steps) with no matching toolstream capture → `qa-verify` overrides its `pass` to `fail`/`blocked` in `verification.json`, exit non-zero; a genuine run (real evidence + matching captures) → all passes verified, exit 0. **AC-3-style** — a checkpoint that dropped `human-action` → qa-verify's re-derivation flags it (redundant with the live gate, but qa-verify is the authority). A `pass` whose bake read-back is unbound (no capture) → overridden. Run → FAIL.
- [ ] **Step 2** — implement `qa-verify.sh` (iterate `checkpoint.json`/journal passes; reuse required-kinds.sh + provenance.sh + check-action-trace.js; write verification.json; exit code). Structure the `QA_VERIFY_REDRIVE_CMD` hook (documented, default-absent = deterministic-only).
- [ ] **Step 3** — tests green (both engines) + no regression (checkpoint 265, action-trace 68, required-kinds 24); dist; validate-adapters; portability. Commit: `feat(enforcement): qa-verify — deterministic out-of-agent re-check + provenance; overrides forged pass (AC-1)`.
