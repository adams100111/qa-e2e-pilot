# qa-kit increment 1 — `/qa-constitution` (stateful-roles core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/qa-constitution` — the first qa-kit step — as a thin orchestration over the **existing** role machinery, adding only the genuinely-new pieces: a deterministic **constitution version/hash** (that later spec snapshots stamp), an **informational role diff** on re-run, and a human-reviewable **`constitution.md`**. No role logic is rebuilt.

**Architecture:** qa-kit's constitution reuses `discovering-user-roles` → `confirming-discovered-roles` → `write-persona-config.sh` (which already regenerate `.qa/config.json` `personas[]` + `.qa/authz-matrix.json` wholesale, ADR-0011). This increment adds the pure, dual-engine helper `constitution.sh` (version-hash + informational diff + `constitution.md` render) + its tests, and **authors** the command body + template as staged files under `core/qa-kit/` — it deliberately does **NOT** wire the command into the shipped build (R2-Q7): increment 2 packages qa-kit as a second plugin and wires `/qa-constitution` then, so it never ships transiently inside the qa-e2e-pilot plugin. This increment's testable deliverable is the helper (fully covered) + the authored files.

**Tech Stack:** Bash + `jq`-preferred/`python3`-fallback (the repo idiom), markdown command body + template. No new dependency. Tests are a bash runner over the pure helper (dual-engine), mirroring `tests/ux-conventions/run.sh`.

## Global Constraints

- **Reuse, don't rebuild, roles.** The authoritative role state is `.qa/config.json` `personas[]` (`[{id, role, plane∈global|contextual, auth}]`) + `.qa/authz-matrix.json` (`[{entity, owningChain[], roleScope{}}]`), generated by `confirming-discovered-roles`/`write-persona-config.sh`. This increment READS that state; it never re-implements discovery or persona-writing.
- **Regenerate-wholesale, never reconcile (ADR-0011).** `/qa-constitution` re-runs the existing flow, which *replaces* `personas[]` wholesale. The diff this increment adds is **informational only** (awareness) — it never merges/preserves per-role edits. All customization is a per-spec concern (a later increment), not the constitution's.
- **Deterministic + dual-engine.** The version/hash and diff must be byte-identical under `jq` and `python3` (honor `QA_ENGINE`), so a spec's stamped constitution version is stable and portable. jq-preferred/python3-fallback/`die` if neither.
- **`constitution.md` is human-only; the machine state is a sibling `.qa/constitution.state.json` (Grill R3-Q4 — PINNED).** `constitution.md` carries the human roles table + a version *line* + a timestamp. The **authoritative machine state** `{roles:[{id,role,plane}], version}` lives in `.qa/constitution.state.json` — robust to parse/diff/stamp, never scraped out of the human markdown. `diff` compares two of these state files; increment 3's `spec-snapshot.sh` reads this file for the version + roles.
- **No harness-specific logic** in the helper (pure bash/jq/py); the command body uses capability-by-name per the plugin conventions. `validate-adapters.sh` byte-oracle + portability stay green.
- **No `grep -P`/`perl`/`node`.** No Claude/Anthropic attribution in commits; no `Co-Authored-By` trailer. Never commit `dist/`.
- **Timestamps:** the command passes a timestamp into the helper (or the helper reads one arg); the helper itself must be deterministic given its inputs (no `date` inside the hashed content) so tests are stable.

## Task 1: `constitution.sh` — version + diff + render helper

**Files:**
- Create: `scripts/qa-kit/constitution.sh`
- Create: `tests/constitution/run.sh`

**Interfaces:**
- `constitution.sh version <personas.json> <authz-matrix.json>` → prints a deterministic hex hash over the **canonical role state**: personas sorted by `id`, each reduced to `"<id>|<role>|<plane>"` (auth EXCLUDED — credentials aren't identity and rotate), joined; then authz rows sorted by `entity`, each `"<entity>|<owningChain joined by ,>|<sorted 'role:scope' pairs joined by ,>"` — **roleScope VALUES are included, not just keys (Grill R2-Q6)**, so `admin: owns → read-scoped` bumps the version; the two blocks concatenated with a separator; hash = a stable digest (see impl). Byte-identical across engines.
- `constitution.sh diff <prev-state.json> <curr-state.json>` → prints JSON `{added:[roleIds], removed:[roleIds], changed:[{id, was, now}]}` comparing two canonical-state objects (`{roles:[{id,role,plane}], version}`); `changed` = same `id`, different `role` or `plane`. Empty prev (`{}` / missing) → all current roles are `added`.
- `constitution.sh state <personas.json> <version>` → prints the machine state JSON `{roles:[{id,role,plane}], version}` (the command writes it to `.qa/constitution.state.json` — the authoritative state, R3-Q4). Deterministic.
- `constitution.sh render <personas.json> <version> <template> <timestamp>` → prints the filled `constitution.md` (**human only** — no fenced state block): the template with `{{ROLES_TABLE}}` (Markdown `id | role | plane`), `{{VERSION}}`, `{{TIMESTAMP}}` substituted. Deterministic given its args.

- [ ] **Step 1: Write the failing tests** (`tests/constitution/run.sh`, dual-engine — mirror `tests/ux-conventions/run.sh`'s `run_engine jq`/`run_engine python3` structure):

```bash
#!/usr/bin/env bash
set -uo pipefail
DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
SH="$DIR/../../scripts/qa-kit/constitution.sh"   # adjust to chosen location
pass=0; fail=0
check(){ if [ "$2" = "$3" ]; then pass=$((pass+1)); else fail=$((fail+1)); echo "FAIL: $1 got=[$2] want=[$3]"; fi; }
run_engine() {
  local E="$1" T; T="$(mktemp -d)"
  printf '%s' '[{"id":"admin","role":"admin","plane":"global","auth":"a@x (seeded)"},{"id":"viewer","role":"viewer","plane":"contextual","auth":"v@x (seeded)"}]' > "$T/p.json"
  printf '%s' '[{"entity":"submission","owningChain":["team_id"],"roleScope":{"admin":"owns","viewer":"read-scoped"}}]' > "$T/m.json"
  # version is deterministic + engine-stable + auth-independent
  local v1 v2; v1="$(QA_ENGINE=$E bash "$SH" version "$T/p.json" "$T/m.json")"
  printf '%s' '[{"id":"admin","role":"admin","plane":"global","auth":"DIFFERENT (seeded)"},{"id":"viewer","role":"viewer","plane":"contextual","auth":"v@x (seeded)"}]' > "$T/p2.json"
  v2="$(QA_ENGINE=$E bash "$SH" version "$T/p2.json" "$T/m.json")"
  check "$E version non-empty" "$([ -n "$v1" ] && echo y)" "y"
  check "$E version auth-independent" "$v1" "$v2"
  # order-independent: reordered personas -> same version
  printf '%s' '[{"id":"viewer","role":"viewer","plane":"contextual","auth":"v@x (seeded)"},{"id":"admin","role":"admin","plane":"global","auth":"a@x (seeded)"}]' > "$T/p3.json"
  check "$E version order-independent" "$(QA_ENGINE=$E bash "$SH" version "$T/p3.json" "$T/m.json")" "$v1"
  # a role change -> different version
  printf '%s' '[{"id":"admin","role":"superadmin","plane":"global","auth":"a@x (seeded)"},{"id":"viewer","role":"viewer","plane":"contextual","auth":"v@x (seeded)"}]' > "$T/p4.json"
  check "$E role-change changes version" "$([ "$(QA_ENGINE=$E bash "$SH" version "$T/p4.json" "$T/m.json")" != "$v1" ] && echo y)" "y"
  # a roleScope VALUE change -> different version (R2-Q6: values, not just keys)
  printf '%s' '[{"entity":"submission","owningChain":["team_id"],"roleScope":{"admin":"read-scoped","viewer":"read-scoped"}}]' > "$T/m2.json"
  check "$E scope-value change bumps version" "$([ "$(QA_ENGINE=$E bash "$SH" version "$T/p.json" "$T/m2.json")" != "$v1" ] && echo y)" "y"
  # diff: added / removed / changed
  printf '%s' '{"roles":[{"id":"admin","role":"admin","plane":"global"},{"id":"guest","role":"guest","plane":"contextual"}],"version":"old"}' > "$T/prev.json"
  printf '%s' '{"roles":[{"id":"admin","role":"superadmin","plane":"global"},{"id":"auditor","role":"auditor","plane":"global"}],"version":"new"}' > "$T/curr.json"
  local d; d="$(QA_ENGINE=$E bash "$SH" diff "$T/prev.json" "$T/curr.json")"
  check "$E diff added auditor" "$(printf '%s' "$d" | python3 -c 'import json,sys;print("auditor" in json.load(sys.stdin)["added"])')" "True"
  check "$E diff removed guest"  "$(printf '%s' "$d" | python3 -c 'import json,sys;print("guest" in json.load(sys.stdin)["removed"])')" "True"
  check "$E diff changed admin"  "$(printf '%s' "$d" | python3 -c 'import json,sys;print(any(c["id"]=="admin" for c in json.load(sys.stdin)["changed"]))')" "True"
  check "$E empty-prev all added" "$(printf '{}' > "$T/e.json"; QA_ENGINE=$E bash "$SH" diff "$T/e.json" "$T/curr.json" | python3 -c 'import json,sys;print(len(json.load(sys.stdin)["added"]))')" "2"
  # render: substitutes + emits a state block
  printf '%s\n' '# QA Constitution' 'VERSION: {{VERSION}} @ {{TIMESTAMP}}' '{{ROLES_TABLE}}' > "$T/tmpl.md"
  local out; out="$(QA_ENGINE=$E bash "$SH" render "$T/p.json" "abc123" "$T/tmpl.md" "2026-09-04T00:00:00Z")"
  check "$E render has version" "$(printf '%s' "$out" | grep -c 'abc123')" "1"
  check "$E render has admin row" "$(printf '%s' "$out" | grep -c '| admin | admin | global |')" "1"
  # state subcommand emits the authoritative machine state (R3-Q4: sibling file, not in the md)
  local st; st="$(QA_ENGINE=$E bash "$SH" state "$T/p.json" "abc123")"
  check "$E state has version" "$(printf '%s' "$st" | python3 -c 'import json,sys;print(json.load(sys.stdin)["version"])')" "abc123"
  check "$E state has admin role" "$(printf '%s' "$st" | python3 -c 'import json,sys;print(any(r["id"]=="admin" for r in json.load(sys.stdin)["roles"]))')" "True"
  rm -rf "$T"
}
command -v jq >/dev/null 2>&1 && run_engine jq
command -v python3 >/dev/null 2>&1 && run_engine python3
echo "constitution: PASS=$pass FAIL=$fail"
[ "$fail" -eq 0 ]
```

- [ ] **Step 3: Implement `constitution.sh`** — header + `has_jq`/`has_py`/`die`/`QA_ENGINE` idiom copied from a sibling (e.g. `ux-conventions.sh`/`journal.sh`). Three subcommands:
  - `version`: build the canonical string (personas → sorted `id|role|plane`; authz → sorted `entity|owningChain|sorted-roleScope-keys`), then hash. **Hash without a new dependency:** use `cksum`/`sha256sum` if present, else a pure `python3 hashlib.sha256`, else a jq-computed fold — pick a deterministic method that's identical across engines (simplest: pipe the canonical string to `python3 -c 'import hashlib,sys;print(hashlib.sha256(sys.stdin.read().encode()).hexdigest()[:16])'` when py present; when jq-only, a documented deterministic reduction — OR just require python3 for the hash and `die` if absent, since python3 is already a hard dep of the repo's other scripts). Keep the canonical-string construction dual-engine; the digest can be python3 (document it).
  - `diff`: parse prev/curr `{roles:[{id,role,plane}]}`, compute added/removed (by `id`) + changed (same id, differing role|plane), print the JSON.
  - `render`: read the template, build the roles Markdown table from personas (`| id | role | plane |`), substitute `{{ROLES_TABLE}}`/`{{VERSION}}`/`{{TIMESTAMP}}`. **Human-only — no fenced state block** (R3-Q4).
  - `state`: map personas → `{roles:[{id,role,plane}] sorted by id, version}` and print it (the command writes this to `.qa/constitution.state.json` — authoritative).
